# Bus via globalThis Symbol

> **Status:** superseded by [ADR 0029 — draw tools with `registerToolRenderer()`](./0029-presentation-via-renderer-resolution.md) (implementation note, 2026-10-14). `core/src/bus.ts` is deleted; cross-package traffic rides the host's own `pi.events`, which is shared process-wide across extensions and so solves the same bootstrapping problem without a global of our own — the reasoning that made a shared singleton necessary still holds, it is just pi's singleton now. Two things do **not** carry over: there is no pre-subscriber queue (`session_start` always runs before anything is emitted, so none was needed), and subscriptions live on the handle rather than on the process, so each one must be unsubscribed on `session_shutdown` and re-taken idempotently at `session_start`.

Cross-package communication uses a global pub/sub bus (`getBus()`) backed by a `globalThis` Symbol key, not dependency injection or explicit event emitter passing. The bus is lazy-initialized on first `getBus()` call and supports event queuing (events emitted before `initBus()` are buffered and flushed on init). This was chosen because pi extensions are loaded independently by pi's extension system — there is no shared application container to inject a bus into. A global singleton avoids the bootstrapping problem of "who creates the bus and passes it to whom." The trade-off is that the bus is implicit (not visible in function signatures) and couples packages to a shared global, but within the pi extension sandbox this is acceptable since all extensions run in the same process.
